1. WHAT THE PROJECT IS
-----------------------------------------------------------------
- Solos Hub: one big Roblox LocalScript (Luau) run by an executor. Admin-style GUI with tabs, sidebar, search,
  themes, key/license system, game picker and per-game modules. Now ~7950 lines, version in the header (v3.18).
- Owner/user: builds this for their own hub + Discord community (https://discord.gg/w7X5R7uSxp).
- Everything runs on the CLIENT. A LocalScript can't change other players for real; effects that work are things the
  game itself trusts the client for (remotes, tools, own character physics). Say so honestly when a feature depends
  on how a game works and can't be verified.

3. HARD RULES / PITFALLS
-----------------------------------------------------------------
- LUAU LIMIT: max 200 local variables active in the main chunk and 60 upvalues per function. CURRENT COUNT:
  146 top-level locals + 50 locals in the key-window do-block = 196 of 200. THERE IS ALMOST NO ROOM. Each new game
  module costs exactly one (`local function loadXxx()`); everything else must live INSIDE that function or in
  tables. If more room is needed, move things into tables (e.g. put helpers in Hub or a module table) or wrap
  top-level code in do ... end blocks. The script silently fails to show if the limit is exceeded.
- NEW MODULAR REFACTOR (v3.19+): Because of the 200-local limit and to save token usage/credits, the project is 
  split up. Individual game modules (mm2.lua, lt2.lua, etc.) are hosted remotely and loaded on-demand via loadstring.
  When writing or updating features for a specific game, NEVER edit or add code to SolosHub.lua. Keep changes entirely 
  isolated to that separate game module file.
- Forward references: a local used before its declaration becomes a nil global. Define helpers above their use.
- `a and nil or b` idiom is buggy - use if/else.
- new(class, props, parent) assigns every prop with o[k]=v, so an invalid property name ERRORS the whole call.
- Don't use `rbxassetid` images the user didn't ask for; web images must be downloaded with the executor
  (request/HttpGet -> writefile -> getcustomasset). See Hub.logoAsset().
- Client HttpService is disabled: network calls go through executor `request`/`http_request`/`syn.request`.
- Executor functions are read through `env` (getgenv() or _G), e.g. env.mouse1click, env.mousemoverel,
  env.mouse1press/mouse1release - always check type(...) == "function" first.
- Anything that talks to a 3rd party (chat relay, key server) must be opt-in/disclosed honestly.
- Don't put keys/secrets in the script. Keys are validated by the user's Cloudflare Worker (VERIFY_URL).
- Don't build anything meant to impersonate real sites/people or steal credentials.
- Toggles with an id are saved to config and re-applied on load. For anything risky pass NO id (like the
  Phantom Forces toggles) or add the id to CONFIG_SKIP so it never auto-enables.

4. SCRIPT ARCHITECTURE (find things with grep; line numbers drift)
-----------------------------------------------------------------
Order in the file (grep the banner text "-- TAB: NAME" etc.):
  header + changelog -> services/locals -> Hub table (data folder helpers, sounds) -> CONFIG/STATE (RANKS, rank,
  hasRank, T theme table, S state table, C registry, Running/Unlocked/Unloading flags, bind(), onUnload()) -> UI
  HELPERS (new, round, Gui, EspGui, notify, copyText, Label, Row) -> MAIN WINDOW -> TABS + COMPONENTS (AddTab,
  selectTab, Section, Toggle, Slider, Button, Input, Keybind, InfoRow, Thumb, PlayerList) -> CHARACTER HELPERS
  (getChar/getHum/getRoot/cam/findPlayer/nearestPlayer/spectate/stopSpectate) -> FEATURE LOGIC -> SLOW TICK ->
  TABS (each in do...end): Dashboard, Player, ESP, Visuals, Players, Teleports, World, Tools, Commands, Settings,
  Chat, Macros, Explorer, Toolbox, Theme, Hub Chat, Combat -> GUI ORGANIZATION (favorites, grouped sidebar) ->
  GLOBAL SEARCH -> HOTKEYS -> KEY WINDOW + LOADING (key window, game picker, game modules, Hub.Games) -> UNLOAD.

Core API (defined near the top; use these, don't reinvent):
  new(class, props, parent)        round(obj, radius)         notify(text, color)       copyText(text)
  bind(signal, fn)                 -> stores connection, auto-disconnected on unload (ALWAYS use for events)
  onUnload(fn)                     -> cleanup callback (restore anything you changed; stop loops via `Running`)
  while Running do ... end         -> loops must check Running so they stop on unload
  AddTab(name, icon) -> page       Section(page, title, subtitle) -> frame
  Tabs[name] = page of any tab     TabButtons[name].Btn = sidebar button   -> game modules add sections to shared
                                   tabs with Section(Tabs["Teleports"], ...), Section(Tabs["Player"], ...)
  Toggle(parent, text, default, cb, minRank, id)  -> obj .Set/.Get/.Fire ; id registers in C[id] (config + commands)
  Slider(parent, text, min, max, default, cb, id) -> obj .Set/.SetSilent/.Get   (integer steps: use v/100 for decimals)
  Button(parent, text, actionText, cb, minRank) -> returns the TextButton (change .Text for cycle buttons)
  Input(parent, label, placeholder, actionText, cb(text, enterPressed)) -> TextBox
  Keybind(parent, text, defaultKeyCode, cb(key), allowClear)   (Enum.KeyCode.Unknown default is fine)
  InfoRow(parent, text) -> TextLabel (update .Text)
  Ranks: "Free User" < "Premium User" < "Owner"; hasRank(min); pass minRank to Toggle/Button to gate.
  T = theme colors (T.Accent, T.Good, T.Warn, T.Bad, T.Sub, T.Text, T.Row, T.Side, T.Hover, T.Btn, T.Off).
  S = shared state; S.Target = selected player; S.SameTeam(p)/S.TeamKey(p)/S.TeamColorOf(p) = team helpers;
  S.Panic() turns universal features off.

REMOTE MODULE SPECIFICATIONS:
  - Game module scripts are loaded dynamically and must accept the core engine environment context. 
  - Every external game script file must strictly unpack the passed parameters at the very first line:
    `local Hub, S, T, C = ...`
  - Modules interact directly with the core layout by referencing the shared global UI tables (e.g. `Tabs["Teleports"]`).

12. MODULES - AS BUILT IN v3.21 (this supersedes the "remote module" notes above where they differ)
-----------------------------------------------------------------
- SolosHub.lua = main hub + Universal only. Games are separate files: mm2.lua, arsenal.lua, pf.lua, lt2.lua, doomspire.lua.
- Hub.ModuleURLs (key-window block, just above Hub.Games) maps game id -> RAW url. Empty url = try the local file
  workspace/SolosHub/mod_<id>.lua (for testing). On pick: Hub.loadGameModule(game) downloads, loadstring()s and runs it
  as fn(Hub, S, T, C). On any failure the hub toasts the reason and falls back to Universal.
- Games in Hub.Games use `remote = true` (no more `load = fn`). To add a game: new entry + new ModuleURLs key + new file.
- Each module starts with:  local Hub, S, T, C = ...  /  local API = Hub.API  /  local Live = API.Live
  then `local X = API.X` lines. Hub.API (built in the main file) exposes: AddTab Button Esp EspGui ICONS InfoRow Input
  Keybind LocalPlayer PlayerGui Players RunService Section Slider TabButtons Tabs Toggle TweenService UIS Workspace bind
  cam copyText env filterTabs getChar getHum getRoot nearestPlayer new notify onUnload round spectate stopSpectate.
  Need another main-file local in a module? Add it to the Hub.API table (costs no local slot) and read it as API.<name>.
- Values that change at runtime must NOT be copied: use Live.Running, Live.Unlocked, Live.BindingActive
  (e.g. `while Live.Running do`, `if Live.BindingActive then return end`).
- Main file is now ~5940 lines; the 5 removed module functions freed 5 local slots in the key-window block.
- Compile check could not run (no Luau in sandbox). Done instead: block-balance check on all 6 files, undefined-name scan on
  the modules, and every Hub.API name confirmed declared before the table is built.
